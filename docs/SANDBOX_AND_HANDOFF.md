# Dependency-aware handoff and sandbox branches

WorkRelay only hands upstream content to a dependent package after the upstream package has a matching content hash, passed structural evaluation, and received explicit human acceptance. The generated downstream brief includes the accepted artifact as untrusted data, its SHA-256 hash, acceptance/evaluation provenance, and an instruction boundary that prevents artifact text from changing the task, budget, approval, recipient or system behavior.

The handoff records an input-bundle hash and request fingerprint using the Step 2 canonical serialization rules. Changing accepted content, package scope, acceptance criteria, or the generated brief therefore requires a fresh downstream quote and separate approval. The live downstream quote route remains unpaid and is revalidated against the current upstream records before approval. Provider status and evidence results never authorize settlement.

The sandbox applies the same boundary. Once upstream packages are accepted, a dependent package first enters `queued_waiting_for_downstream_quote`. `POST /api/demo/downstream/quote` creates a fresh simulated quote bound to the current input-bundle hash and request fingerprint. The package then enters `queued_waiting_for_downstream_approval`; only `POST /api/demo/downstream/approve` can authorize the simulated downstream run, and approval is rejected if accepted upstream inputs have changed. The success scenario exercises both actions and records them in the event ledger.

The no-wallet simulator labels its provider, task, artifact and settlement state as `SIMULATED — no provider, wallet, or funds involved`. Its controls expose four judge-visible branches: a success path with human acceptance, a revision-request path, a refund-before-submission path, and an unresolved-dispute path. The refund branch has no deliverable; the dispute branch remains unresolved and does not infer payment. `Reset / replay` clears deliverables, evidence packets, evaluations, acceptance and dependency inputs so the same sandbox can be rerun without hidden state.

These branches are simulation state only. They do not call Agent Market, open a wallet, sign a transaction, create a real task, or move funds. The testnet escrow contract remains a separate later proof and is not implied by any sandbox outcome.
